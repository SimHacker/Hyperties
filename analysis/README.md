The raw archive is **not too big for ordinary Git**. Its main problems are redundant layouts, binary readability, runtime coupling, private material, and permissions, not GitHub's large-file threshold.

The existing working tree had 5,447 staged entries when first inspected. The earlier committed content was only the initial [root README](../README.md). All staging was subsequently cleared with your approval; the index was verified empty. Ignoring a staged file does not remove it from Git's index.

## Reproduce

Requirements: Node.js 20+, `file`, and `strings`; no npm packages or network upload.

The original inventory scripts require no npm packages. Semantic recovery now
requires a build of the shared TypeScript core (`npm --prefix tools ci`, then
`npm --prefix tools run build`). Dependencies are build-time TypeScript/esbuild
only; historical data is not uploaded.

```sh
node analysis/analyze.mjs
node analysis/inspect.mjs
node analysis/curate.mjs
node analysis/verify.mjs
node analysis/catalog.mjs
node --test analysis/records.test.mjs
node analysis/recover-book.mjs --allow-partial
node analysis/build-reading-room.mjs
```

Run from the repository root. The scripts resolve the root from their own location. They read original files and write only into this analysis directory. 

The ZIP reader checks each decompressed member's length and CRC32, then computes SHA-256 and compares with all loose contents. It does not extract to disk or execute software. It explicitly rejects unsupported ZIP methods, encryption, ZIP64, multipart archives, and undecodable legacy names rather than calling them duplicates. The legacy ARC reader parses headers only; see [the ARC caveat](formats.md#archives).

Checksums verify identity, not usefulness or safety. Identical files can have necessary separate roles in runnable layouts. Different hashes may differ only in an executable length field and padding. Neither a checksum nor a privacy regex can decide copyright clearance.

## Tools worth using

- `shasum -a 256`: available on macOS; `shasum -a 256 -c analysis/SHA256SUMS` verifies the snapshot from the repository root.
- `jdupes` / `fdupes`: exact duplicate discovery. Use listing modes first, not deletion or hard-link replacement. The scripts here already provide hashes and explicit membership without installing anything.
- `rmlint`: duplicate and lint discovery; inspect any generated removal script rather than running it blindly.
- `file` and a hex viewer: signatures, not authoritative schemas. This archive produces many false positives; [formats](formats.md) explains them.
- `unzip -l`, `unzip -t`: ZIP listing/integrity. A matching archive and directory name is **not** proof of identical payload.
- `lsar` / `unar`, or a historical ARC utility in an isolated emulator: potential ARC readers. Neither `lsar` nor `unar` was installed; the available `bsdtar` rejected the ARC.
- `pdftotext`, `pdfinfo`, `textutil`: already available and used for manual and later-document interpretation.
- ImageMagick `magick` and FFmpeg: already available; likely PCX/GIF/FLI access-copy tools. Keep conversions lossless and inspect results; these were not batch-converted.

No deduplication packages were installed, no original executable was run, and no original data was sent to an external service.

## Semantic recovery iteration

The [record readers](records.mjs) and [catalog builder](catalog.mjs) now parse
the observed loose-article structure and both classic index dialects. They
recover titles, section boundaries, links, aliases, directives, local-resource
candidates and explicit parse failures without exporting private genealogy or
full article bodies. Generated semantic outputs are local and ignored by Git.
Eight tests cover synthetic edge cases, real museum/book evidence, and complete
catalog counts and private-directory exclusions.

The LZW iteration recovered 218 book articles including the six hyper-joke
records, with 49 byte-for-byte ACM cross-checks. The subsequent
[adaptive arithmetic recovery](arithmetic-format.md) solved all 30 remaining
records and matches 113 CACM originals byte-for-byte. Sixteen tests cover
records, indexes and both codecs; four additional tests cover the reading
room's opt-in definition speech. The generated reading room presents all 650
records across the book and museum, with no remaining book decoding gaps.
[Shared TypeScript core](../tools/README.md) is used in Node and
bundled into the browser; historical-file inventories exclude `tools/` as well
as analysis and Git storage.
